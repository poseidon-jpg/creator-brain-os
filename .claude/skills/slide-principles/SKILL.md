# Slide Principles

Most slide advice is about how a slide *looks* - fonts, grids, colour, spacing. That is the easy
half. This skill covers the other half: what a slide *says*, how it gets *seen*, how it *sticks*,
how it respects the brain's *limits*, and how its data *argues*. That is the half that closes deals.

Use it on top of whatever visual style or brand you build in. It does not replace a design system,
it makes the design system land.

## How to use this

When asked to build or improve a slide or deck, run every slide through the 5 jobs below, in order.
A slide is not done until it passes all five. When critiquing a deck, name which job each weak slide
is failing.

The 5 jobs:

1. **Say it straight** - decide what it says before how it looks.
2. **Win the glance** - earn the first 3 seconds.
3. **Make it stick** - survive the look-away.
4. **Ease the load** - respect the brain's limits.
5. **Let data argue** - make the chart prove the point.

---

## Job 1 - Say it straight

**P1. Lead with the answer.**
Open with the conclusion; make every later slide support it. Do not save the point for the end.
*Why:* people decide relevance from the conclusion, then choose how deep to go.
*In a deck:* slide 1 is one sentence stating the takeaway. The rest is evidence under it.
*Source: Barbara Minto, The Pyramid Principle.*

**P2. Titles are takeaways, not topics.**
Write each slide title as a full-sentence claim ("Churn fell 40% after the onboarding fix"), never a
label ("Churn").
*Why:* a sentence headline forces one clear point and carries it even at a glance.
*In a deck:* make every `<h1>`/`<h2>` a complete claim; the body is the visual evidence, not bullets.
*Source: Minto (action titles) + Michael Alley (assertion-evidence).*

**P3. Ride the contrast rhythm.**
Alternate "what is" and "what could be" so the deck has an arc, not a flat list of facts.
*Why:* the gap between now and possible is tension the audience wants resolved - that pull holds them.
*In a deck:* tag slides what-is / what-could-be and alternate them; end on the new reality.
*Source: Nancy Duarte, Resonate (the Sparkline).*

## Job 2 - Win the glance

**P4. One message per slide.**
If a slide needs two ideas, it is two slides.
*Why:* two messages split attention; a slide is glance media, grasped in about 3 seconds.
*In a deck:* one claim per slide. Overflow becomes a new slide, never a second column.
*Source: David JP Phillips (Death by PowerPoint) + Duarte (glance media).*

**P5. Make one thing pop.**
Give a single element one preattentive cue - one accent colour or one size jump - and mute everything
else. Look away, look back: your eye should land where the audience's will.
*Why:* the visual system flags a single deviating element in under 250ms, before conscious thought.
*In a deck:* exactly one accent per slide, on the one element that matters. Everything else neutral.
*Source: Ware / Few / Knaflic - preattentive attributes.*

**P6. Cap it at six.**
Keep distinct objects on a slide to six or fewer.
*Why:* small sets are read instantly (subitizing); past about six the brain switches to effortful
counting and people disengage.
*In a deck:* hard-cap distinct elements at 6; if there are more, split the slide.
*Source: David JP Phillips - the subitizing limit.*

## Job 3 - Make it stick

**P7. Let the picture carry it.**
Lead each slide with a meaning-carrying visual; demote text to a caption.
*Why:* words alone are recalled at about 10% after three days; add a picture and it is about 65%.
*In a deck:* visual first, words second. Aim for near-zero 40-word text slides.
*Source: John Medina, Brain Rules - the picture superiority effect.*

**P8. Concrete beats abstract.**
Turn every claim into a tangible number or image ("saves 4 hours a week", not "improves efficiency").
*Why:* the brain remembers "1,000 songs in your pocket" far better than "large storage capacity".
*In a deck:* replace abstract copy with a concrete figure, object, or comparison.
*Source: Chip & Dan Heath, Made to Stick - the Concrete principle.*

**P9. Build one unforgettable beat.**
Designate one slide as the peak - a shocking stat, a full-bleed image, or one sound-bite line - and
style it bigger than everything around it.
*Why:* memory encodes high-arousal moments far more strongly than flat information.
*In a deck:* one full-bleed slide, one giant statement, no clutter. Let it breathe.
*Source: Nancy Duarte - the S.T.A.R. moment ("Something They'll Always Remember").*

## Job 4 - Ease the load

**P10. Don't put your script on the slide.**
On-screen prose you also say out loud competes with your own voice. Put sentences in speaker notes.
*Why:* reading and listening to the same words at once overloads one channel; recall drops toward zero.
*In a deck:* the slide gets a short cue plus a visual. The full script lives in notes, never on screen.
*Source: Richard Mayer (redundancy principle), echoed by Godin and Phillips.*

**P11. Labels touch the thing they name.**
Put each callout right beside its element; kill the far-off legend.
*Why:* a label far from its referent burns working memory holding it while you hunt for the match
(measured effect size g = 0.63).
*In a deck:* annotate directly on or next to the element with a short connector. Avoid separate legends.
*Source: Richard Mayer - spatial contiguity.*

**P12. Empty space is working.**
Treat negative space as a design element, not waste. Do not fill it.
*Why:* space directs the eye to what is left and reads as quality; every element should earn its place.
*In a deck:* generous margins on purpose; remove logos, footers, and decoration that do no work.
*Source: Garr Reynolds, Presentation Zen - empty space and signal-to-noise.*

## Job 5 - Let data argue

**P13. Pick the chart from the message, not the data.**
Read the headline's verb first, then choose the form.
*Why:* picking a chart by habit makes the visual and the claim disagree; the verb keeps them matched.
*In a deck:* classify the claim, then map it:
- "compare / rank" → bar
- "share of a whole" → stacked bar or 100% column
- "trend / change over time" → line
- "spread / frequency" → histogram
- "relate / correlate" → scatter
*Source: Gene Zelazny (Say It With Charts) + Andrew Abela (Chart Chooser).*

**P14. Start with gray.**
Default every series to gray, then earn back one colour for the element that carries the point.
*Why:* if everything is coloured, nothing leads the eye; one earned colour is an instruction.
*In a deck:* render charts gray by default; recolour only the message element in the accent.
*Source: Cole Knaflic (Storytelling with Data) and Jon Schwabish, independently.*

**P15. One chart, one point.**
Label directly on the chart and untangle spaghetti into small multiples - one trend per panel.
*Why:* in-chart labels cut the eye's round-trip to a legend; small multiples each read in one glance.
*In a deck:* put labels on the lines and bars; split 5+ tangled series into a grid of mini-panels.
*Source: Jon Schwabish - integrate graphics and text, avoid the spaghetti chart.*

## Quick checklist (run before shipping any deck)

1. Does slide 1 state the conclusion? (P1)
2. Is every title a claim, not a topic? (P2)
3. Does the deck swing what-is / what-could-be? (P3)
4. One message per slide? (P4)
5. Does exactly one thing pop on each slide? (P5)
6. Six objects or fewer? (P6)
7. Is a visual carrying the meaning, not text? (P7)
8. Are claims concrete numbers, not abstractions? (P8)
9. Is there one unforgettable beat? (P9)
10. Is your script in notes, not on the slide? (P10)
11. Do labels touch what they name? (P11)
12. Is there deliberate empty space? (P12)
13. Does each chart match its headline's verb? (P13)
14. Is everything gray except the one point? (P14)
15. One chart, one point, no spaghetti? (P15)

## Animate the slides (ONLY when the user asks for motion)

Skip this whole section unless the user wants their slides or principles **animated** - a motion
deck, an interactive page, a landing page, "make it move". By default Slide Principles is just the
rules; bring out the motion stack only on request. When you do, pick the tool by what the motion
needs. The rule: **declarative motion → CSS. Stateful / interactive / physics motion → React.**

### CSS is the default (entrances, idle loops, hovers, reveals)

Zero dependencies, fast, robust. Reach for a framework only when a keyframe genuinely can't do it.

- Drive everything with `@keyframes` + `transition`.
- **Stagger** with an index custom property: `style="--i:3"`, then
  `animation-delay: calc(var(--i) * .1s)` so items cascade in.
- **Spring feel without JS:** overshoot easing, e.g. `cubic-bezier(.34,1.56,.64,1)`.
- **Idle motion** = an `infinite` loop keyframe (a gentle bob, a flicker, a drifting wave).
- **Always** wrap motion in `@media (prefers-reduced-motion: no-preference){ … }` for accessibility.
- **Replay an entrance** by toggling a class and forcing a reflow:
  `el.classList.remove('go'); void el.offsetWidth; el.classList.add('go');`
- Ceiling: CSS is fire-and-forget - no state, no gestures, no logic. When you need those, go React.

### React + Framer Motion when motion needs STATE, GESTURES, or PHYSICS

Drag-to-reorder, click-to-select, a live slider that re-animates, count-ups, list add/remove with
spring physics. Run it in the browser with **no build step** via ESM + `htm` (so any plain `.html`
file works - paste and open):

```html
<script type="module">
import React, { useState, useEffect } from 'https://esm.sh/react@18.3.1';
import { createRoot } from 'https://esm.sh/react-dom@18.3.1/client';
import { motion, AnimatePresence, Reorder, animate }
  from 'https://esm.sh/framer-motion@11?deps=react@18.3.1,react-dom@18.3.1';
import htm from 'https://esm.sh/htm@3.1.1';
const html = htm.bind(React.createElement);   // write components without a JSX build
</script>
```

- `motion.div` with `initial` / `animate` / `transition={{ type:'spring', stiffness, damping }}`
  for physics-based entrance and layout changes.
- `whileHover` / `whileDrag` for gesture feedback; `Reorder.Group` + `Reorder.Item` for draggable
  lists that reflow with `layout`.
- `AnimatePresence` for enter/exit; `animate(0, target, { onUpdate })` for animated count-ups.
- State (`useState`) drives the visuals live - e.g. a "focus" slider that mutes every element
  except the accent in real time. None of that is possible in pure CSS.

### Choosing, in one line

If the motion plays the same every time, it's **CSS**. If the user can change it while it runs
(drag, click, slide, add, remove), it's **React + Framer Motion**. Never fake a state machine in
CSS; never pull in a framework for a fade-in. Whatever brand or design system the deck uses still
applies on top - this section is only about *how the motion is built*.
