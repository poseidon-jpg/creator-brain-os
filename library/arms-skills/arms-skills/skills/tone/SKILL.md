# /tone

Your voice, written down so your agent stops guessing. This skill is a small database, not a long list of steps. The agent reads it before it writes in your name, and it gets better every time you correct a draft.

## Where your voice lives

Read only what the job needs:

- **Your voice** (this file, below): the principles for each register. Short on purpose.
- **Samples**: [references/samples.md](references/samples.md). Your real writing and speech, plus before and after corrections. Read it before writing more than a few lines.
- **Format**: [references/format.md](references/format.md). How each channel displays text (character caps, line breaks, what bold does).
- **Copywriting voices**: [references/copy-masters.md](references/copy-masters.md). Six borrowable voice modes for posts. Pick one per post.
- **Short-form scripts**: [references/shorts.md](references/shorts.md). The shape for reels, Shorts and TikToks.

## First run (when "Your voice" below is empty)

Fill the starter before the first real draft. It takes about 10 minutes.

1. **Collect your writing.** Ask the user to paste 3 to 10 things they wrote or said that sound like them: posts, emails, a video transcript, a newsletter. If they point to a folder or a link, read it there. Mix channels if you can.
2. **Ask 4 quick questions**, numbered, in one message:
   1. Who do you write for, in one line?
   2. Which spelling do you use (US, UK, Australian, other)?
   3. Any words or phrases you never want to see in your name?
   4. How do you open and sign off a post, if you have a habit?
3. **Write the starter.** Put each sample in `references/samples.md` with its channel and one line on why it sounds like the user. Then write 3 to 6 principles per register under "Your voice", each with its reason, taken only from what the samples and answers show. Leave a register empty if there is no evidence for it yet.
4. **Show the user the principles** in chat and fix anything that is off. Then delete the "Empty until the first run..." line under "Your voice" and start the real task.

"(empty)" under a register is how you know the first run hasn't happened for that register yet. Replace it with principles once there is evidence.

## How to use it on every job

1. Pick the register: spoken, chat or written.
2. Read that register's principles below, then the samples that match the channel.
3. Draft. Check the channel's rules in `format.md`.
4. Run the checklist at the bottom before showing the user.

## How to absorb a correction

When the user corrects a draft's wording, rhythm or word choice, the fix lands here in the same turn, not in whatever skill was running.

1. Apply the fix to the current draft first.
2. Find the principle that explains the correction. Ask "what is true about how this person sounds that made my version wrong?"
3. Rewrite the existing principle around it, or add one if nothing covers it. Write the reason, not the date. "Short lines, because the reader is on a phone" lasts. "Short lines, added on March 3" gets ignored.
4. Add the before and after to `samples.md` under Corrections when it would teach the next draft.
5. Delete anything the new principle makes redundant. A good correction often makes this file shorter.

Never append dated rules under each other. Never make the user say the same thing twice.

## Before showing any draft

1. Read it aloud in your head. Any line a person would not say gets rewritten.
2. Check it against the register's principles and the "Never" list above.
3. Scan for common AI tells: "it's not X, it's Y" flips, inflated praise ("a testament to"), a list of three by reflex, the same word three or more times, a closing offer phrased as a question.
4. Check line and character limits for the channel in `format.md`. Count them, don't guess.
5. If a check fails, fix that line and run the list again.
